> **阶段一交付物**（未写代码）。

## 一、需求与约束回顾

| 项 | 内容 |
|---|---|
| 核心链路 | 输入目的地 + 时间 → 大模型 API 生成攻略 → **开源世界地图**上按序打点连线 |

## 二、先核实你提到的 4 个项目（重要）

我逐个查了 GitHub，结论如下——**有两个和你的想象不一致**，避免后面选型踩空：

| 你提到的 | 核实结果 | 与需求相关度 |
|---|---|---|
| **TREK** | ✅ 真实存在且高度相关：`liketrek/TREK`，14.8k★ | ⭐⭐⭐ 核心参照 |

## 三、项目调研（逐个整理）

### 1. liketrek/TREK ⭐14.8k · TypeScript · AGPL-3.0

- **活跃度**：2026-03 创建，2026-10-17 仍在提交；297+ open issues（本次调研时为 34，增长很快）。
- **核心功能**：自托管行程规划；实时多人协作、交互式地图、PWA、SSO(OIDC)、预算、打包清单、照片集成(Immich/Synology)、航班导入(AirTrail)、交通活动、地点搜索(Nominatim)、路线规划。
- **技术栈**：npm workspaces 单体仓库（client/server/shared 三层）；前端 **React 19**（强制统一版本）；后端 Node；Docker/Alpine；sharp 出图标；DB 推断 Postgres；实时协作推测 WebSocket。
- **架构**：React SPA + Node API + 共享类型；Docker 部署；插件式外部集成。
- **Issue 痛点（按评论数）**：
  - 性能：`#218` Trip tab 在 60+ 地点时严重卡顿（21 评）。
  - 第三方集成脆弱：Immich（`#24` 16评、`#1948` HTTP406 13评）、Synology（`#500`）、Nominatim 报错（`#576`）、Google Maps API 失效（`#26`）。
  - 自托管升级痛苦：Docker 升级 v3.1.x 启动失败（`#1221` 12评）、v3.3.0 后频繁崩溃（`#1576`）。
  - 路线/显示：住宿间无活动时的路线（`#1297`）、航班线缺失（`#850`）。
  - 登录鉴权：iOS 登录（`#294`）、无法登录（`#280`）、改密码失败（`#318`）、无法建管理员（`#1339`）。
  - 移动端：iOS 15 白屏（`#1028`）。
- **优点**：功能最全、社区最热、协作/预算/打包一体化。
- **缺点**：**重**（自托管门槛高）、规模上去性能掉、外部依赖多易坏、AGPL 限制商用、迭代快导致升级事故多。

### 2. seanmorley15/AdventureLog ⭐3.8k · Svelte · **GPL-3.0**（2026-10 调研新增）

- **活跃度**：2024-03 创建，2026-10-14 更新；**235 open issues**（数量偏多）；主页 adventurelog.app。
- **核心功能**：自托管旅行追踪 + 行程规划；地图标注"足迹"、照片、地点收藏、世界旅行进度统计、分享。
- **技术栈**：前端 **SvelteKit** + Tailwind 4 + daisyUI + allauth；后端 **Django + Django REST Framework**；Docker + nginx 部署；DB 推断 Postgres/PostGIS。
- **架构**：SvelteKit SPA + Django REST API + 容器化部署（前端/后端/nginx 多容器）。
- **Issue 痛点（按评论数）**：
  - **部署是最大痛点**：`#237` Tailscale/Wireguard 访问方式困惑（34评，被额外 nginx 容器搞晕）、`#671` 在 ZimaOS/Debian NAS 上部署失败、登录注册 500 错误（24评）。
  - **升级迁移事故**：`#318` 升级后 `column adventures_adventure.date does not exist`，数据全打不开（25评）。
  - **平台兼容**：`#205` 镜像不兼容树莓派 ARM（20评）；`#1039` **Safari/iPhone/iPad 上大量按钮无响应、几乎不可用**（15评，疑与 Safari 对无 href 动态元素点击处理有关）。
  - **数据/功能缺口**：`#257` 国家列表只有 21 个，要求换外部数据集（24评）；`#657` 添加地点时 "No location found"（16评）。
- **优点**：SvelteKit 轻量现代、地图足迹玩法清晰、上手比 TREK 简单。
- **缺点**：Django 重型后端（对我们过重）、**235 个 open issue 说明质量/维护压力大**、Safari 兼容坑、GPL-3.0 copyleft（允许商用但衍生必须开源）。

### 4. gpxstudio/gpx.studio ⭐1.2k · MDX/TS · MIT

- **活跃度**：2026-10-09 更新；110 open issues。
- **核心功能**：在线 GPX 创建/编辑/查看；路线绘制、轨迹可视化、地形/3D、导入导出。
- **技术栈**：`gpx` TS 解析库 + `website` **SvelteKit 2 / Svelte 5**；地图 **MapLibre GL 6 + maplibre-gl-geocoder + OpenStreetMap + GraphHopper 路由 + Mapterhorn 地形**；immer + Dexie(IndexedDB 离线) + Tailwind 4 + shadcn-svelte；Vite 6 + adapter-static（**纯静态站**）。
- **架构**：**纯前端静态站，无后端**；IndexedDB 离线；路线依赖外部 GraphHopper。
- **Issue 痛点**：
  - **路线引擎依赖脆弱**：`#325` "Road Bike routing unusable since a few days"（**60 评！外部路由服务一波动，核心功能就瘫**）。

> 📌 **这是"开源世界地图 + 单页应用"的最佳架构参照**：SvelteKit 纯静态 + MapLibre + 无后端。

### 5. opentripplanner/OpenTripPlanner ⭐2.7k · Java · LGPL

- **核心功能**：开源多模态路径规划引擎（OSM 路网 + GTFS 公交），算 A-B 点的公交/步行/骑行组合路线。
- **技术栈**：Java；需构建路网+公交数据图（OSM.pbf + GTFS zip），内存与磁盘开销大。
- **架构**：独立后端服务，暴露 REST API。
- **对我们的意义**：**它是"真实路线计算"的开源答案，但需要服务器 + 数据构建**，与"单文件双击即开"根本冲突。仅在未来要做"公交换乘方案"时才有价值。
- **痛点/缺点**：数据构建门槛高（几 GB 输入、数小时构建）、内存敏感、版本升级要重跑图。

### 6. 开源世界地图底座（本次调研的核心新增）

这是替换腾讯地图的真正候选池：

| 项目 | ★ | 语言 | 许可证 | 定位 | 判断 |
|---|---|---|---|---|---|
| **Leaflet** | 45.8k | JS | BSD-2 | 最流行的轻量 2D 地图库，栅格瓦片为主 | 备选：最轻、生态最大，但动画/矢量能力弱 |
| **Cesium** | 15.8k | JS | Apache-2.0 | 3D 地球/地图引擎 | 不选：几百 KB~MB 级依赖，对"2D 打点连线"过重 |
| **MapLibre GL JS** | 11.9k | TS | BSD 系 | **WebGL 矢量瓦片地图库**，Mapbox GL v1 的社区 fork | ✅ **主选** |
| **OpenFreeMap** | 6.2k | Python | **MIT** | **免费矢量瓦片托管**（OSM 数据），公开实例免 Key 免注册 | ✅ **主选（底图）** |
| **tileserver-gl** | 2.9k | JS | BSD | 自托管瓦片服务器（MapTiler 出品） | 备选（自托管路线） |
| **protomaps-leaflet** | 857 | TS | BSD | Leaflet 的矢量瓦片渲染插件 | 备选（若选 Leaflet） |

#### OpenFreeMap 详细（重点）
- **是什么**：用 OSM 数据 + Planetiler 生成的全球矢量瓦片，免费托管。MIT 许可，商用允许。
- **公开实例政策（官方 README 原文）**："completely free: there are **no limits on the number of map views or requests**. There's **no registration, no user database, no API keys, and no cookies**."
- **技术架构（有意思）**：不跑瓦片服务器，而是把 3 亿个小文件（平均 450 字节）做成 **Btrfs 分区镜像 + 硬链接**，直接由优化过的 nginx serve；专用服务器（非云）；Round-Robin DNS 负载均衡；每周三全星球更新。
- **接入方式**：`https://tiles.openfreemap.org/styles/{positron|liberty|bright|dark}`，瓦片 `/planet/latest/{z}/{x}/{y}.pbf`。
- **⚠️ 明确不提供（by design）**：**地理编码/搜索、路径规划/导航、静态图、栅格瓦片、卫星影像、高程、自定义数据集**。
- **⚠️ 无 SLA**，靠捐赠维持服务器；自托管需 Ubuntu 24.04 跑它的部署脚本，或下载每周星球 Btrfs/MBTiles/**PMTiles**（约 90GB 级）。
- **Issue 痛点**：`#22` 地图多语言翻译（58评，开放）、`#31` 户外/徒步样式（42评，开放）、`#19` 地形/山体阴影（41评，已关闭并并入 #31）、`#114` 生产域名 CORS 403（11评，已关闭）、`#16` PMTiles 延迟、`#112` 改样式 403。

#### 我在本机对相关端点的实测（2026-10-18）

| 端点 | 结果 | 结论 |
|---|---|---|
| `tiles.openfreemap.org/planet/latest`（TileJSON） | HTTP 200 + `Access-Control-Allow-Origin: *` | ✅ 浏览器可直连 |
| `tiles.openfreemap.org/styles/{positron,liberty,bright,dark}` | 全部 200 + CORS `*` | ✅ 四种样式可用 |
| `unpkg.com / cdn.jsdelivr.net` 的 maplibre-gl@4.7.1 | 200 | ✅ CDN 可用 |
| `unpkg.com` leaflet@1.9.4 | 200 | ✅ |
| **Photon（photon.komoot.io，OSM 地理编码）** | 能返回数据（中文名正常），**但响应无 `Access-Control-Allow-Origin` 头** | ❌ **浏览器不能直连** |
| **Nominatim（nominatim.openstreetmap.org）** | 本机连接失败（http 000） | ❌ 本机不可达；且有官方 1 req/s 策略 |

## 四、从调研中提炼的共性教训（直接指导设计）

1. **规模一上去就卡**（TREK #218，60+ POI）→ 按天渲染、切天清空图层，单屏 POI 永远个位数。
2. **分类配色要从第一天内置**（trip #15 是功能请求）→ 四色分类直接做进数据模型。
3. **外部服务依赖是最大风险源**（gpx.studio #325 路由服务波动 60评、TREK 的 Google Maps/Nominatim/Immich、trip 的 Google Places #160）→ **每加一个外部依赖，都要问"它挂了页面还能看吗"**；能本地算的就本地算（直线连线、LLM 直出坐标）。
4. **自托管 / 鉴权 / 升级 = 三重痛苦**（TREK、AdventureLog、trip 全是重灾区）→ 单文件零部署零鉴权，天然规避。
5. **Safari/iOS 是被遗忘的战场**（TREK iOS 白屏、AdventureLog #1039 Safari 按钮全废）→ 响应式 + 事件绑定方式要保守（用 `click` 而非依赖 `href`）。
6. **免费公共服务无 SLA**（OpenFreeMap 靠捐赠、OSRM demo 是演示服务器）→ 底图地址做成**可配置常量**，一个字段就能切换到自托管。
7. **许可证要看**（TREK AGPL、AdventureLog GPL-3.0 都限制衍生开源）→ 我们只借鉴架构不拷代码，最终产物 MIT/自有许可，干净。

## 五、适配需求的落地方案

### 5.1 总体思路

**保持现有单文件 HTML 形态，只把"地图层"整体换掉**：

```
用户输入（目的地 + 起止日期）
   ↓
通用大模型（OpenAI 兼容）→ 返回 N 天结构化 JSON（含每个 POI 的 WGS-84 经纬度）
   ↓
渲染：banner 徽章 + DAY Tab + 四色时间轴卡片   ← 完全复用现有实现
   ↓
地图层（新）：MapLibre GL JS + OpenFreeMap 瓦片，按天画 marker + 连线，卡片↔地图联动
```

**最大的简化**：腾讯地图那一套（申请 Key、GCJ-02 坐标、Geocoder 服务类）全部删除，换成 **MapLibre + OpenFreeMap + LLM 直出坐标**，页面从"填 Key 才能用地图"变成 **"打开联网就能看地图"**。

### 5.2 技术栈选型与理由

| 维度 | 选型 | 理由 | 备选 |
|---|---|---|---|
| 地图渲染库 | **MapLibre GL JS（v4/v5）** | WebGL 矢量瓦片；`flyTo`/`fitBounds` 平滑动画；marker/popup/line 图层齐全；与 OpenFreeMap 原生配套；gpx.studio 已在生产验证 | Leaflet（更轻，但动画和矢量能力弱一截） |
| 底图瓦片 | **OpenFreeMap 公开实例** | 免费、**无 Key、无注册、无请求上限**、MIT、CORS `*`、四种官方样式、周更；已实测 200 | 自托管 tileserver-gl；OSM 栅格（策略受限且本机不通） |
| 默认样式 | **positron**（浅灰极简） | 与 Stripe 风格最贴合；其余 liberty/bright/dark 可做切换器 | — |
| **坐标解析** | **大模型直接输出 WGS-84 经纬度（主）** | 唯一能同时满足"开源/免 Key/浏览器跨域/零额外依赖"的方案；著名 POI 坐标 LLM 基本准确 | 见下方说明 |
| 坐标精修（可选） | Nominatim（用户自行开关，失败静默） | 官方 OSM 地理编码；但本机不可达 + 1 req/s 策略，**不能当唯一依赖** | Photon（无 CORS 头，浏览器直连不可行，需代理） |
| 连线方式 | **顺序直线连线（默认）** | 零外部依赖、瞬时完成；规避 gpx.studio #325 那类"路由服务一挂全坏" | OSRM demo（CORS `*` 实测可用）做"真实驾车路线"开关 |
| 路线引擎（远期） | OSRM 自托管 / OpenTripPlanner | 需要真实公交换乘时再上，需服务器 | — |
| 大模型 | 通用大模型（OpenAI 兼容 `/chat/completions`） | 上一轮已确认；不变 | — |
| 交付形态 | **单文件 HTML**（CSS/JS 内联）+ CDN 引 MapLibre | 双击即开；MapLibre 约 800KB，CDN 比内联合理 | 提供"本地 vendor"模式（把 `maplibre-gl.js/css` 放同目录） |
| 坐标系 | **全链路 WGS-84** | OSM/MapLibre 原生就是 WGS-84，**比原来腾讯 GCJ-02 更简单、无需转换** | — |

#### ⚠️ 关于坐标解析的重点说明（本次方案的技术核心）

调研实测证明：**开源侧没有"免费 + 免 Key + 浏览器跨域可用"的地理编码服务**（Photon 无 CORS 头、Nominatim 本机不可达且有速率策略）。因此采用**分层策略**：

1. **主路径**：让大模型在生成 JSON 时**直接给出每个 POI 的 `lat`/`lng`（WGS-84/GPS 坐标）**。著名景点/餐厅/商圈的坐标 LLM 通常准确到几十米级，对城市级行程可视化完全够用。
2. **精修路径（可选开关）**：若用户开启，对每个 POI 调 Nominatim 校验/修正，失败则静默保留 LLM 坐标。
3. **兜底**：两者都失败 → 该 POI 不画点，只在卡片上标注"暂无坐标"，不阻断整体渲染。
4. **提示词注意**：必须明确要求 LLM 输出 **WGS-84（GPS）坐标**，不要输出国内地图（高德/百度）的偏移坐标——中国区偏移通常在几十到几百米，城市尺度可接受，但要知情。

### 5.5 关键风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| OpenFreeMap 公开实例无 SLA、靠捐赠 | 底图可能不稳定/关停 | 底图 URL 做成可配置常量；预留自托管（tileserver-gl / 下载区域 PMTiles）切换文档 |
| LLM 输出的坐标不准或缺失 | 点位偏移/缺失 | 提示词约束 + 可选 Nominatim 精修 + 无坐标降级展示 |
| LLM 输出国内偏移坐标（GCJ-02） | 中国区偏移几十~几百米 | 提示词明确 WGS-84；城市尺度可接受，需知情 |
| 大模型 API 的 CORS | 生成失败 | 沿用上一轮结论：建议用支持浏览器跨域的兼容服务；保留"载入示例"兜底 |
| MapLibre 需联网加载（CDN + 瓦片） | 离线不可用 | 提供本地 vendor 模式；首次加载失败给出明确提示 |
| OSM 在中国部分区域 POI 覆盖不足 | 底图细节少 | 主要城市覆盖良好；可提示用户 |
| WebGL 不可用（极老设备/浏览器） | 地图黑屏 | 检测 WebGL 支持，失败时降级提示（可改 Leaflet 栅格路线） |

## 八、二次迭代：视觉升级 + 详细偏好（2026-10-18）

### 8.1 底图样式对比结论

| 样式 | 观感 | 结论 |
|---|---|---|
| **Positron** | 极简浅灰、对比度低 | 之前默认，显得“素”，已改为备选 |
| **Liberty** | 细节丰富、配色自然、**唯一带 `fill-extrusion` 3D 建筑** | ✅ **新默认** |
| Bright | 鲜艳、信息量大但偏 busy | 备选 |
| Fiord | 冷蓝灰、优雅 | ✅ 已加入切换器 |
| Dark | 过黑，白天阅读吃力 | 备选 |

> OpenFreeMap 官方第 6 个「3D」样式**没有公开 URL**（`/styles/3d` 返回 404）。3D 视角改用 **Liberty + `easeTo({pitch:55, bearing:-20})`** 实现，利用其建筑挤出图层。

### 8.2 Cesium 地球升级

- 接入 **NASA GIBS Blue Marble** 真实地球影像：
  `https://gibs.earthdata.nasa.gov/wmts/epsg3857/best/BlueMarble_ShadedRelief_Bathymetry/default/GoogleMapsCompatible_Level8/{TileMatrix}/{TileRow}/{TileCol}.jpeg`
- 公有领域、免 Key、CORS `*`，用 `Cesium.WebMapTileServiceImageryProvider` 加载。
- 保留国界线、经纬网、目的地光柱/光环；视觉从“线框球”变为真实地球。

### 8.3 详细偏好输入（9 维）

同行人 / 节奏 / 预算档位 / 交通方式 / 每天点位数 / 住宿区域 / 兴趣多选（8 项）/ 必去必吃 / 明确不想要。
偏好持久化到 `travel_prefs_v1`，并作为独立段落注入大模型 user prompt；约定取舍优先级：

> **必去/必吃 > 兴趣偏好 > 节奏 > 预算**；「明确不想要」一律不安排。

### 8.4 路线与观感再升级（17:00）

- **默认样式改为 Bright**（观感最好）；Liberty 保留，用于 3D 建筑。
- **默认路线改为 OSRM 真实道路**（不再默认直线）：
  - 自驾 / 打车 → `driving`；公共交通 / 步行 → `foot`；实测两个 profile 均可用。
  - 紫色路线 + 白色描边；地图头部显示「真实驾车/步行路线」状态；失败自动回退直线。
