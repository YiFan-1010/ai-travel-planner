# 行程规划 · AI 旅行路线规划器

> 输入目的地和天数，AI 生成可落地的多日行程，并在真实地图上还原每天的真实道路路线。

一个纯前端单页应用。地图用 MapLibre + OpenStreetMap 全链路免 Key 数据，行程由大模型流式生成，路线走 OSRM 真实路网，坐标精确到街区。

## 核心功能

**行程生成**
- 9 维偏好输入：同行人 / 节奏 / 预算 / 交通方式 / 每日点位数 / 住宿 / 兴趣 / 必去 / 不想要
- 流式生成，实时显示「已规划 2 天 · 8 个地点」与字符进度
- 生成结果自动落盘，下次打开自动恢复

**地图可视化**
- 每日行程按天配色，点位编号与卡片一一对应
- 真实道路路线（OSRM），三层描边 + 生长动画 + 沿弧线流动光点
- 点位与路网之间的**接驳虚线**（OSRM 会把坐标吸附到最近道路，偏远地点可达 300 米以上，用虚线如实呈现这段距离）
- 3D 建筑拉伸 + 地形起伏，卫星影像双源（NASA GIBS 宏观 / Esri 城市级）按缩放分档淡出

**世界模型**
- MapLibre globe 投影，从球体一路放大到街区，无级切换不跳变
- 地点搜索（Photon 双路 + 行政区层补位），落点居中 → 坐标校准 → 平滑放大

**其他**
- AI 调整行程（自然语言修改，diff 定位变化的天）
- 每日时间轴拖拽排序
- 导出行程长图（Canvas 手绘 1080 × 2x）
- 深色主题（View Transition 圆形扩散切换）
- 命令面板（⌘K）
- 离线降级（Canvas 手绘示意图）

### 数据源与许可

| 用途 | 服务 | 许可 / 说明 |
|---|---|---|
| 底图矢量瓦片 | [OpenFreeMap](https://openfreemap.org/) | 基于 OpenStreetMap，免费无 Key |
| 地理编码 | [Photon](https://photon.komoot.io/) | Komoot，基于 OSM，免费无 Key |
| 地理编码备选 | [Nominatim](https://nominatim.org/) | OSM 官方，免费，有速率限制 |
| 路线规划 | [OSRM](http://project-osrm.org/) | Demo 服务，免费无 Key |
| 卫星影像（宏观） | [NASA GIBS](https://gibs.earthdata.nasa.gov/) | Blue Marble，公有领域 |
| 卫星影像（城市级） | [Esri World Imagery](https://www.arcgis.com/home/item.html?id=10df2279f9684e4a9f6a7f08febac2a9) | 需署名，商用建议自托管 |
| 大模型 | DeepSeek / 任意 OpenAI 兼容端点 | 用户自备 Key |

**全链路零 API Key 成本**（除大模型），不依赖高德、腾讯、百度等商业地图服务。

## 快速开始

```bash
npm install
npm run dev          # http://127.0.0.1:5173
```

生产构建：

```bash
npm run build        # 类型检查 + 打包到 dist/
npm run preview      # 预览构建产物
```

> 如果只想看看效果，`archive/v1-single-file.html` 是工程化之前的单文件版本，
> 双击即可运行，不需要 Node 环境。

首次使用需要配置大模型 API Key：

1. 点击右上角齿轮 → API 配置
2. 填入 Base URL（默认 `https://api.deepseek.com`）、Model（默认 `deepseek-chat`）、API Key
3. 配置**只保存在浏览器 localStorage**，不会写入代码或上传

没有 Key 也可以点击「载入示例」查看内置的成都 3 日行程。

## 关键技术决策

**为什么不用高德 / 腾讯地图**
商业地图的坐标是 GCJ-02 偏移坐标，与 OSM、OSRM、卫星影像的 WGS-84 混用会产生 300-700 米错位。本项目全链路统一 WGS-84，提示词强制模型输出 WGS-84，禁止 GCJ-02 / BD-09。

**为什么路线用 OSRM 而不是直线**
直线连接会让"一天之内从城东跑到城西再回城东"这种不合理行程看不出来。OSRM 走真实路网，行程是否可行一眼可辨。

**为什么地图飞行不用 `flyTo`**
`flyTo` 的 zoom 曲线是指数式的，2.5 秒就冲完 43% 路程，观感突兀；一次性 `easeTo` 跨 14 级会让 `tile.z` 追不上 `transform.zoom`，超出 overscale 后整屏不渲染。改为「对准 → 校准 → 逐帧推 zoom」三段式，中心锁死。

## 已知限制

- OSRM 官方 Demo 服务有速率限制，批量生成时可能部分失败（已做直线兜底 + 状态提示）
- Nominatim 国内访问较慢（实测 10 秒以上），仅作 Photon 结果不足时的补位
- 大模型给出的坐标偶有偏差，界面会提示「坐标可能不准」
- 底图瓦片无法离线，离线时降级为 Canvas 示意图
