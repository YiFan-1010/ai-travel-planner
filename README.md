# 行程规划 · AI 旅行路线规划器

> 输入目的地和天数，AI 生成可落地的多日行程，并在真实地图上还原每天的真实道路路线。

**在线体验**：https://ai-travel-planner-09617.app.workbuddy.host/?sharecode=4TJPTBB5G4

不需要注册、不需要填 API Key，打开输入「杭州 3 天」就能生成。
（分享链接必须带上 `?sharecode=` 参数，否则会被拦截）

一个 Vite + TypeScript 单页应用 + 一层 Node 代理。地图用 MapLibre + OpenStreetMap 全链路免 Key 数据，行程由大模型流式生成并经工具核对真实坐标，路线走 OSRM 真实路网。

## 核心功能

**行程生成**
- 9 维偏好输入：同行人 / 节奏 / 预算 / 交通方式 / 每日点位数 / 住宿 / 兴趣 / 必去 / 不想要
- 流式生成，实时显示「已规划 2 天 · 8 个地点」与字符进度
- 生成结果自动落盘，下次打开自动恢复

**地图可视化**
- 每日行程按天配色，点位编号与卡片一一对应
- 真实道路路线（OSRM），三层描边 + 生长动画 + 沿弧线流动光点
- 点位与路网之间的**接驳虚线**（OSRM 会把坐标吸附到最近道路，偏远地点可达 300 米以上，用虚线如实呈现这段距离）
- 3D 建筑拉伸 + 地形起伏，卫星影像双源（NASA GIBS 宏观 / Esri 城市级）按缩放分档淡出

**多方案对比**
- 同一目的地可生成穷游 / 舒适 / 带娃 / 文艺四套方案，各有独立提示词
- 结果页出现方案条，一键切换，每套方案各自保留自己的拖拽排序与 AI 调整
- 只有两个以上方案时才出现，单方案不占版面

**世界模型**
- MapLibre globe 投影，从球体一路放大到街区，无级切换不跳变
- 地点搜索（Photon 双路 + 行政区层补位），落点居中 → 坐标校准 → 平滑放大

**其他**
- AI 调整行程（自然语言修改，diff 定位变化的天）
- 每日时间轴拖拽排序
- 导出行程长图（Canvas 手绘 1080 × 2x）
- 深色主题（View Transition 圆形扩散切换）
- 命令面板（⌘K）
- 离线降级（Canvas 手绘示意图）

## AI 架构

v1 是一次调用让模型直接吐出含经纬度的 JSON。v2 改成带工具的编排流水线：

```
规划 ──→ 落地 ──→ 体检 ──→ 修正
 │        │        │        │
模型只定   并发调用  跨度/缺口  问题清单
主题与地点 地理编码   密度检查   回喂模型
```

1. **规划**：模型只决定「去哪、怎么排、为什么这么排」，不碰坐标
2. **落地**：并发调用地理编码工具，把地名换成真实坐标
3. **体检**：单日跨度、地点缺口、点位密度
4. **修正**：把问题清单回喂模型，最多一轮，只改有问题的部分

### 工具层

| 工具 | 作用 | 数据源 | 实测 |
|---|---|---|---|
| `searchPlace` | 地名 → 真实坐标 | 高德 / Photon | 高德 0.5s |
| `geocodeAll` | 批量并发 + 退避重试 + 熔断 | — | 11 个点约 4s |
| `routeFeasibility` | 真实里程与耗时 | OSRM | 1.5s |
| `haversine` | 球面距离 | 本地计算 | 即时 |

### 坐标可信度是分级的

| 模式 | 触发条件 | 精度 |
|---|---|---|
| 工具定位 | 配置了高德 Key | 可到门牌 |
| 模型坐标 | 无可用地理编码服务 | 大致位置，靠路线校验兜底 |

**为什么要有两条路**：Photon 和 Nominatim 在国内被 DNS 污染（实测解析到 `10.161.x.x`
内网地址和 Dropbox 的 IP），完全不可达；高德可用但需要申请 Key。
没配 Key 的用户不应该被卡住，所以降级路径必须存在。

### 坐标系处理

内部全程 WGS-84。只在调用高德时做一次 `GCJ-02 → WGS-84` 转换（三轮迭代逼近，误差 < 1m），
偏移绝不外溢到地图、路线、存储层。

| 路线规划 | [OSRM](http://project-osrm.org/) | Demo 服务，免费无 Key |

| 大模型 | DeepSeek / 任意 OpenAI 兼容端点 | 用户自备 Key |

## 快速开始

```bash
npm install
npm run dev          # http://127.0.0.1:5173
```

生产构建与本地运行完整版（含 API 代理）：

```bash
cp .env.example .env # 填入 DEEPSEEK_API_KEY / AMAP_KEY
npm start            # 构建 + 启动 http://127.0.0.1:8080
```

### 两种运行形态

应用会启动时探一次 `/api/health` 自动判断，用户不需要选择：

| 形态 | 触发条件 | 用户的感受 |
|---|---|---|
| **服务端代理** | 存在 `/api` 且服务端配了 Key | 打开就能用，不用填 Key，有每日限额 |
| **自带 Key** | 纯静态托管（无 `/api`） | 引导去设置里填自己的 Key |

填了自己的 Key 时**优先走直连**，不消耗服务端额度；留空才走代理。
两条路的前端逻辑完全一致，只是请求地址不同。

### 不想装 Node

`archive/v1-single-file.html` 是工程化之前的单文件版本，双击即可运行，
但它是纯静态形态，必须自己填 Key。

## 部署

### 为什么需要一个服务端

Key 放在前端等于公开：打包后的 JS 里明文可读，任何人 F12 都能拿到并刷爆额度。
所以线上必须有东西替用户持有 Key。`server/` 就是这一层，只有 400 行，零依赖。

### 方式一：任意支持 Node 的平台（推荐）

```bash
npm run build
npm run serve        # 或 PORT=3000 node server/index.mjs
```

一个进程同时提供静态页面与 `/api`，SSE 流式完整支持（不经过任何缓冲层）。

平台侧只需两个环境变量：

| 变量 | 说明 |
|---|---|
| `DEEPSEEK_API_KEY` | 大模型 Key，没有则前端退化为「要求用户自带」 |
| `AMAP_KEY` | 高德 Web 服务 Key，没有则坐标退化为模型自估 |

其余可选变量见 `.env.example`。

### 方式二：Docker

```bash
docker build -t ai-travel-planner .
docker run -p 8080:8080 \
  -e DEEPSEEK_API_KEY=sk-xxx \
  -e AMAP_KEY=xxx \
  ai-travel-planner
```

`Dockerfile` 是两阶段构建，最终镜像只含 `dist/` 与 `server/`，不含源码、依赖与任何 `.env`。

### 方式三：纯静态（无代理）

```bash
npm run build
# 把 dist/ 整个丢到任意静态托管
```

此时前端自动切换到「自带 Key」模式，用户需要自己填。

### 密钥与限额

- `.env` 在 `.gitignore` 与 `.dockerignore` 双重排除，从未进入 Git 历史
- 服务端对每个 IP 做三层限流：小时、天、全局天，默认 12 次/小时/人
- 前端打包产物里搜不到任何 Key —— 这是这套架构存在的全部理由

> 评委/访客拿到链接直接能用，不用注册、不用申请 Key，也不需要知道 Key 是什么。

## 关键技术决策

**为什么不用高德 / 腾讯地图**
商业地图的坐标是 GCJ-02 偏移坐标，与 OSM、OSRM、卫星影像的 WGS-84 混用会产生 300-700 米错位。本项目全链路统一 WGS-84，提示词强制模型输出 WGS-84，禁止 GCJ-02 / BD-09。

**为什么路线用 OSRM 而不是直线**
直线连接会让"一天之内从城东跑到城西再回城东"这种不合理行程看不出来。OSRM 走真实路网，行程是否可行一眼可辨。

**为什么地图飞行不用 `flyTo`**
`flyTo` 的 zoom 曲线是指数式的，2.5 秒就冲完 43% 路程，观感突兀；一次性 `easeTo` 跨 14 级会让 `tile.z` 追不上 `transform.zoom`，超出 overscale 后整屏不渲染。改为「对准 → 校准 → 逐帧推 zoom」三段式，中心锁死。

## 已知限制

- OSRM 官方 Demo 服务有速率限制，批量生成时可能部分失败（已做直线兜底 + 状态提示）
- Nominatim 国内访问较慢（实测 10 秒以上），仅作 Photon 结果不足时的补位
- 大模型给出的坐标偶有偏差，界面会提示「坐标可能不准」
- 底图瓦片无法离线，离线时降级为 Canvas 示意图
